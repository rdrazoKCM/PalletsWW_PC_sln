## 🎯 1. Objetivo General de la Propuesta

El objetivo de esta mejora es eliminar por completo la "caja negra" que experimentan tanto el operador como los supervisores durante el guardado de pallets, dividiendo la solución en dos frentes complementarios:

1. **Nuevo Log Especializado en SQL Server (`dbo.tblLog_PalletsWipes_SQLPasos`):**
   Registrar con precisión milimétrica cada Stored Procedure y acción individual que se dispara durante el guardado de pallets (ej. `pa_P009_01006_tblPalletsInsertcmdV5`, `pa_P009_01002_sLlenardgvProduccion`, `pa_P009_01006_tblPalletsTotalTarimas`, impresión ZPL, etc.), guardando sus tiempos de ejecución individuales en milisegundos, estatus y posibles errores.

2. **Consola Visual en Vivo en la Aplicación ("Pantallita a un Costado del Grid"):**
   Incorporar en el formulario principal `frm_001_Pallets`, a la derecha de `dgvDatos1`, un panel visual moderno de telemetría en tiempo real que vaya narrando paso a paso al operador lo que el sistema va ejecutando:
   - *"Paso 1: Validando candado anti-duplicidad en memoria (0 ms)..."*
   - *"Paso 2: Ejecutando SP pa_P009_01006_tblPalletsInsertcmdV5 (reservando tarima TXWW...)..."*
   - Si la red se atrasa: *"⚠️ Esperando confirmación de red del servidor... (8.5 s)"*
   - *"Paso 3: Actualizando contadores en pa_P009_01002_sLlenardgvProduccion (14 ms)..."*
   - *"Paso 4: Enviando etiqueta ZPL a impresora (177 ms)..."*
   - *"✅ Transacción completada con éxito."*

## 📋 3. Detalle de Componentes a Implementar

### A. Base de Datos (`TLX022MXDB`)

1. **Nueva Tabla de Logs por Acción/SP:** `dbo.tblLog_PalletsWipes_SQLPasos`
   ```sql
   CREATE TABLE dbo.tblLog_PalletsWipes_SQLPasos (
       IdLogPaso         BIGINT IDENTITY(1,1) NOT NULL PRIMARY KEY,
       IdTransaccion     UNIQUEIDENTIFIER NOT NULL,
       FechaHora         DATETIME2(3) NOT NULL CONSTRAINT DF_tblLogSQLPasos_Fecha DEFAULT (SYSDATETIME()),
       PasoNumero        INT NOT NULL,
       NombreSP          NVARCHAR(100) NOT NULL,
       Accion            NVARCHAR(150) NOT NULL,
       TiempoMs_SQL      INT NOT NULL,
       Estatus           NVARCHAR(20) NOT NULL, -- 'OK', 'ERROR', 'TIMEOUT', 'WARNING'
       FolioVale         INT NULL,
       NoTarima          NVARCHAR(50) NULL,
       NoMaquina         INT NULL,
       NombreEquipo      NVARCHAR(50) NULL,
       NoUsuario         INT NULL,
       DetalleInfo       NVARCHAR(1000) NULL
   );

   CREATE INDEX IX_tblLogSQLPasos_Transaccion ON dbo.tblLog_PalletsWipes_SQLPasos (IdTransaccion, PasoNumero);
   CREATE INDEX IX_tblLogSQLPasos_FechaHora ON dbo.tblLog_PalletsWipes_SQLPasos (FechaHora);
   ```

2. **Nuevo Procedimiento Almacenado de Registro de Paso:**
   `dbo.pa_P009_01006_tblLogSQLPasosInsert`
   Recibe los parámetros del paso y los inserta de manera ligera sin interferir en la transacción principal.

### B. Aplicación Cliente (`clsA_P035_PallestWipes`)

1. **Nuevo Módulo de Gestión de Consola y Telemetría por Pasos:**
   - Archivo: `clsU\clsU_LiveExecutionMonitor.vb`
   - Se encarga de:
     * Registrar el inicio de cada paso con `Stopwatch` de alta precisión.
     * Enviar el texto formateado al control visual de la pantalla con colores temáticos (verde para éxito, amarillo para proceso, rojo para error o advertencia de red).
     * Guardar el paso asíncronamente en segundo plano (`ThreadPool.QueueUserWorkItem`) en `dbo.tblLog_PalletsWipes_SQLPasos` para **no alentar en lo más mínimo la aplicación**.

2. **Ajuste Visual del Formulario Principal (`frm_001_Pallets.vb` y `.Designer.vb`):**
   - Actualmente `dgvDatos1` tiene un ancho de `1239 px` (donde sus 10 columnas solo ocupan `1115 px`).
   - Se ajusta `dgvDatos1.Width = 890 px`.
   - Se agrega a la derecha el panel `pnlLiveMonitorSQL`:
     * `Location = (902, 583)`
     * `Size = (345, 292)`
     * Encabezado oscuro moderno (`#0F172A`) con título y semáforo.
     * Lista o caja de texto de consola con scroll automático (`RichTextBox` o `ListBox` oscuro `#1E293B` con texto `#34D399` / `#38BDF8`).
     * Barra inferior con resumen métrico de la última operación: `SQL Neto: X ms | Red: Y ms | ZPL: Z ms`.

3. **Instrumentación del Flujo de Guardado en `clsF_001_frm_001_Pallets.vb` y `clsU_00901_dgv.vb`:**
   Durante el evento de guardado, la aplicación emite los siguientes eventos en vivo:
   - **Paso 1:** `VALIDACION_PREVIA` (Candados de 38 renglones y hora duplicada en RAM).
   - **Paso 2:** `SP_INSERT_PALLET` (`pa_P009_01006_tblPalletsInsertcmdV5`), midiendo tiempo de ida y vuelta. Si supera 3 segundos, la consola alerta en tiempo real: *"⚠️ Latencia de red alta en llamada a SP"*.
   - **Paso 3:** `SP_LLENAR_PRODUCCION` (`pa_P009_01002_sLlenardgvProduccion`).
   - **Paso 4:** `SP_LLENAR_TURNO_ANT` (`pa_P009_01002_sLlenardgvProduccion`).
   - **Paso 5:** `IMPRESION_ETIQUETA` (Envío TCP puerto 9100).
   - **Paso 6:** `SP_CONTADORES_TARIMA` (`pa_P009_01006_tblPalletsTotalTarimas`).
   - **Paso 7:** `REFRESCO_GRID` (Sincronización final con el vale).

## ⚡ 4. Garantía de Rendimiento: Cero Impacto en Velocidad

Para asegurar que la aplicación **no se vuelva lenta**:
1. **Actualización de la Consola Visual:**  
   Se realiza en la UI con llamadas inmediatas sin recargas pesadas.
2. **Envío de Logs a SQL Server:**  
   Se despacha de forma **100% asíncrona** en segundo plano mediante `ThreadPool.QueueUserWorkItem`. Si la red tiene retardo, el hilo de fondo se encarga de guardar el log mientras la pantalla del operador queda libre de inmediato.
3. **Persistencia SQL:**  
   La tabla `tblLog_PalletsWipes_SQLPasos` contará con índices optimizados en `IdTransaccion` y `FechaHora` para inserciones en < 2 milisegundos.
